How it works

Warden guards the box. Beacon lights it up.

Under the hood

Built in Go, on the metal, with the panel wherever it fits.

wardend · Go 1.25
One static binary, no runtime to install.

The daemon is a single Go executable with an embedded scheduler, SQLite store and TLS. It starts in milliseconds, idles at a few MB of RAM and leaves the CPU and memory of the machine to the servers themselves.

$ ls -la wardend
-rwxr-xr-x 1 warden warden 19M wardend
transport · WebSocket + REST
Live by default.

Console lines, state changes, metrics samples and task progress are pushed over a single authenticated WebSocket the moment they happen. REST covers the rest. No polling loops, no page refreshes.

ws › console · state · events
ws › metrics (2 s) · tasks
jwt first message · Ed25519
beacon · Next.js, separate service
The panel is its own deployable.

Beacon only signs you in and serves the UI; the browser talks to wardend directly. Run it as a container next to the daemon (the installer offers it) or on a separate host or Dokploy, depending on how many nodes you manage.

Features

Everything a server admin does, with the server's own data.

Instances

Pick the software, the version, the build. Done.

Paper, Purpur, Fabric and Vanilla from their official catalogs. wardend downloads the jar, verifies its hash, writes the EULA and server.properties, and selects a managed Temurin runtime that matches the Minecraft version.

Console & supervision

The console you know, plus a daemon that never sleeps.

Live log over WebSocket with the original levels, command history, staged stop. When the server crashes, wardend brings it back with exponential backoff; TPS is polled quietly every 16 s and the reply stays out of your view.

Plugins

Hangar and Modrinth, one search box.

Search both catalogs, queue several plugins, pick a version for each and install them in a batch — every jar hash-verified. Update checks, enable/disable and manual uploads live in the same table. Paper and Purpur only; the tab hides elsewhere.

Metrics

Sampled every two seconds, kept for a week.

CPU, RAM, network and TPS per instance from the process itself — no plugin needed. One hour in memory for the live charts, seven days in SQLite for the "what happened last night" question. Host CPU, memory and disk on the Home page.

Players

The history the server already keeps, in one card.

Sessions from the log, advancements and statistics from the world folder, skins from Mojang. Message, kick, ban or op a player without opening the console — whitelist, ops and bans stay in sync with the files.

Backups & upgrades

Scheduled, compressed, restorable.

save-off, flush, tar.zst with a sidecar manifest, all inside the daemon. Retention by count or total size. Restore takes a safety copy first; upgrading the server build takes a backup before it swaps the jar.

Two commands on a fresh Ubuntu box.

The installer writes the systemd unit, picks a TLS mode and can start the Beacon panel as a container next to the daemon.

curl -fsSL https://github.com/manuelvegadev/warden/releases/latest/download/wardend-linux-amd64 -o wardend
chmod +x wardend && sudo ./wardend install
